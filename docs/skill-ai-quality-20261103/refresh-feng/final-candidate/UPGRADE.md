# 双风最终候选：安装、升级与回滚

目标为无名杀 1.11.7。此前 `fcc9eb2581e9470e228dea112add930fa0be0e07` 与对应两个 ZIP 和组合补丁通过独立交付验收；本目录是后续候选，须按本目录校验值和验收报告确认，不代表已经发布。外部集成回执 pending。

## 安装前：两种方案二选一

先退出宿主，完整备份扩展目录、宿主 character/shenhua.js、character/refresh.js 和已有安装记录。安装器只检查扩展内文件，不能自动识别所有原生补丁或第三方修改；须人工核对宿主源码、补丁记录和其他扩展的接管范围。状态不明时先在隔离副本核实，不要继续。

### 方案 A：原生组合补丁

从干净的 1.11.7 宿主开始，停用两个风包扩展策略。对宿主根目录先运行 `git apply --check dual-feng-native-candidate.patch`，通过后运行 `git apply dual-feng-native-candidate.patch`。不得叠加两份旧单包补丁或同技能扩展接管。回滚前退出宿主；确认文件没有其他修改后运行 `git apply --reverse --check` 和 `git apply --reverse`，或从事前备份恢复；如有第三方改动先人工核对，勿强行覆盖。

### 方案 B：扩展安装

确认相关宿主原生 AI 未打补丁。分别解压两个 ZIP 到独立目录，从各自目录运行 `node integration/apply-pack.mjs --extension-root "<无名AI扩展目录>" --dry-run`，检查结果后去掉 `--dry-run` 安装。两包均须使用同一候选版本；任意顺序安装，完成后重启宿主。不得与方案 A 叠加。

## 旧版升级、其他扩展与回滚

退出宿主并备份全部目标文件和 `.djsc-pack-backups` 安装记录。使用每个旧包自身的 `node integration/rollback-pack.mjs --extension-root "<无名AI扩展目录>"` 按记录回滚。核对注册表及所有其他扩展对共享核心的引用；其他使用者仍在时不得替换共享核心。若旧核心或完整 CRLF 检出与新包冲突，安装器会拒绝写入；只有确认所有使用者已安全回滚且备份可恢复时，才人工迁移到包内精确字节并重新预检。安装器不会自动合并或自动迁移。未知内容、BOM、混合行尾或第三方修改均需人工处理。

回滚新版时退出宿主，分别运行各包的 rollback 命令。注册表和文件若被其他人修改，默认拒绝危险回滚；先检查差异和安装记录，不要用 `--force` 绕过。共享核心及空注册表可能保留，切勿因目录为空或看似多余而递归删除其他扩展的数据。需要恢复迁移前原始字节时，先确认没有其他使用者，再从独立备份恢复。

## 校验和故障恢复

在交付目录执行 `Get-FileHash -Algorithm SHA256 <文件>`，与 `SHA256SUMS.txt` 逐项核对；解压后可运行 `python verify.py --zip <ZIP路径>`。哈希不一致时不要安装。找不到目标根目录时检查 `--extension-root` 是否指向含 `score/index.js` 的无名AI扩展。核心、对包或注册表冲突时停止，保存错误和原始文件，按上述步骤检查；安装中断时保留事务记录并重试预检或按安装器提示恢复，禁止手动删除未知备份。原生补丁预检失败时不要强行应用；用干净宿主和备份核对。
