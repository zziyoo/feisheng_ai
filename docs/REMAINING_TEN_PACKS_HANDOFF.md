# 剩余十包独立验收交接

目标宿主为无名杀 1.11.7，开发分支为 `codex/remaining-ten-packs`，起点为六包统一交付基线 `75eb630fd259def3f42afea8f9bbb823a9eb71af`。每个分包的逐技能审查、遗留风险、源文件和验收场景见 [开发台账](REMAINING_TEN_PACKS_PROGRESS.md)。

本轮选择原生 AI 补丁路线。原因是多数改动涉及内嵌评分、原生技能标签或发动评估，现有六包的所有权注册和构建配置已有既定范围。新补丁只改宿主 AI 条件或评分。仓库中六包运行文件、扩展注册表、共享核心、构建配置和历史任务快照沿用基线。未注册新的扩展分包。当前构建器只支持六个既有包，本轮交付物是开发补丁及审查记录。

## 应用与撤销

用无名杀 1.11.7 的干净 LF 宿主副本验证，每个分包补丁位于 `docs/remaining-ten-packs/native/`。从宿主副本的 `resources/app` 目录执行以下操作，绝对路径指向该分包补丁：

```powershell
git -c core.autocrlf=false apply --check "<补丁绝对路径>"
git -c core.autocrlf=false apply "<补丁绝对路径>"
# 验证完成后可在同一宿主副本撤销
git -c core.autocrlf=false apply -R --check "<补丁绝对路径>"
git -c core.autocrlf=false apply -R "<补丁绝对路径>"
```

重复应用会因旧上下文不匹配而被拒绝。先做 `--check`，按宿主需要选择包；同一技能的原生与扩展接管仍遵循六包基线的二选一部署要求。肉林的两个武将使用同一技能 ID，补丁只在神话林修改一次。界林的 `reluanwu` 继承神话林的乱武评分，界山的 `oltuntian` 继承神话山的屯田评分。验收这些变体时要分别跑单包及搭配相应神话补丁的固定局面。十包补丁对彼此的静态应用检查不等于与六个已验收分包共同安装的行为验收。

## 独立验收优先场景

1. **选择流程与异常**。缔盟全友方且存在合法零成本目标对，身份乱武无主公，化身只有当前武将牌或候选技能评级低于返回。检查选择退出、合法结果和回合推进。
2. **隐藏信息**。交换未知手牌的牌面或点数且保持公开状态相同，复验铁骑、同疾、屯田、神话及界限制霸、界限缔盟。再验证公开牌、控制视角和虚拟响应。
3. **收益和合法成本**。验收遗计、机捷、急援、神智、淑慎、骁果、节命、好施、溃诛和明任。优先覆盖获牌限制、濒死即时用牌、受保护装备、目标座次并列、实际收益上限、确认受伤才弃整手及后续转换技。
4. **未改的宿主边界**。复核空池化身、奇制目标没有可弃置牌、飞军支付后才出现合法目标、界巧变在零标记下的弃牌上下文、旧版忘隙与界标派生结算收益差异。若要改动，先确定该问题属于 AI 回调还是宿主规则。
5. **部署**。在干净 1.11.7 宿主分别应用补丁并撤销。需要与既有六包共存时，单独验证共享 ID 及继承技能的影响和扩展卸载。对先前已验收的六包使用原有验收记录。

## 开发检查与剩余问题

- 从宿主源码复核十个包的武将技能列表，台账 81 名武将、164 条技能关联无遗漏或重复登记。
- 在同一隔离 LF 宿主副本应用十份补丁，四个受影响的 JavaScript 文件通过语法检查。按逆序撤销，四个文件恢复原始字节。新增补丁改动的宿主源码行与四个现有正式原生补丁的改动行无重叠。
- 用原始回调与打补丁后的回调执行局部固定输入。标准四包 8 项、神话三包 7 项、界限三包 9 项，修复后 24/24 通过。合计 23 项在原回调上复现，1 项为不变对照。使用模拟宿主接缝，未启动真实对局。
- P0 风险方面，缔盟空候选与乱武缺主公导致的回调异常已有补丁。化身初始池完全耗尽的异常候选留待确认真实宿主可达性，修复可能涉及宿主结算。
- P1 方面，已修复的隐藏牌读取、错误收益和选择流程见各包章节。奇制保护牌、界巧变弃牌上下文仍待验证规则口径。忘隙沿用既有逻辑，因为界标派生继承该回调但结算不同。
- P2 方面，飞军同量付费后的可行动机会、拼点与装备机会成本等见台账。飞军需要完整选牌过程验证，当前只确认原 AI 估值没有计算支付后的张数。
- 本轮只完成开发与静态核对，真实宿主验收、安装共存及正式 ZIP 由独立验收阶段处理。
